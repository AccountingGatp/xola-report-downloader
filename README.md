# Xola Report Downloader – deploy on Vercel (free)

1. **Accounts:** tick one or more (checkboxes, with Select all / Clear).
2. **Report:** the two Xola portal reports below.
3. **Dates:** From / To with shortcuts (Yesterday, Last 7 / 30 days, This month, Last month, Year to date).
4. **Download.** All ticked accounts are fetched at the same time. One account gives one `.xlsx`; several accounts give one ZIP with one `.xlsx` per account.

## Reports (layout copied from real portal downloads)

| Report | Looks like the portal file | Date used |
|---|---|---|
| **Cash Flow Report** | `Xola_transactions_...xlsx`: sheets *Report Details*, *Summary*, *Transactions* (23 columns) | transaction date ("Date is between") |
| **Purchase Items** | `Xola_purchaseItems_...xlsx`: sheets *Events*, *Reservations* (two header rows with merged groups), *Worksheet* | arrival (trip) date |

Times are shown in the account's own time zone, like the portal. Dates are real Excel date-times (same look as the portal's, not text formulas).
Tick "Also show raw API data reports" to get plain CSV/Excel dumps of every field Xola returns (used for troubleshooting).

## Check the first download against the portal

The sheets, columns, order, merges and formats were checked cell by cell against the two portal exports. What is **not** yet confirmed is which Xola API field feeds each column (it needs a run with the real API key).
If a main column comes back empty from Xola, the page shows a yellow "Check these columns" notice and leaves the cell blank (never a made-up 0).
The field names are listed in one place: the `CF` and `PI` tables at the top of `api/_portal.js`.

Assumptions to confirm: Cash Flow includes the transaction types purchase, purchase_affiliate, deposit, balance, refund and modify (not payouts or subscriptions); Purchase Items is filtered by arrival date; "Generated by" name and email come from the two boxes on the page (or `XOLA_REPORT_NAME` / `XOLA_REPORT_EMAIL`).

## If Xola says "refused the request (403)"

The message names the exact Xola address that was refused. The same `XOLA_API_KEY` as the Empire Categoriser works for payouts, but some keys cannot read the full account list or an account's details.
- The app then finds the accounts from your recent payouts. If that also fails, set `XOLA_SELLERS` in Vercel, for example `{"Amsterdam Tours":"<sellerId>"}`, and redeploy. Seller ids appear in the Xola address bar or in the Categoriser's payout list.
- If the account's time zone cannot be read, set `XOLA_TIMEZONE` (e.g. `Europe/Amsterdam`); otherwise the page warns that dates are assumed to be UTC.
- Check the key was pasted with no quotes, spaces or line break, and redeploy after changing it.

## Deploy (about 10 minutes)

1. Put this folder in a **private** GitHub repository.
2. vercel.com → **Add New → Project** → import the repo → Deploy (no build settings).
3. **Settings → Environment Variables**, add:
   - `APP_PASSWORD` – a password for your team
   - `XOLA_API_KEY` – your Xola API key
   - `XOLA_SELLERS` *(optional)* – only if the account list comes up empty or incomplete: `{"Account name":"sellerId", ...}`
   - `XOLA_TIMEZONE` *(optional)* – fallback time zone (e.g. `Europe/Amsterdam`) if Xola does not return one for an account
   - `XOLA_REPORT_NAME`, `XOLA_REPORT_EMAIL` *(optional)* – default "Generated by" details
   - `XOLA_BASE` *(optional)* – defaults to `https://xola.com/api`
   - `XOLA_DATE_EPOCH` *(optional)* – set to `1` if Xola ignores the date filters (sends epoch seconds instead of plain dates)
4. **Deployments → ⋯ → Redeploy**.
5. Open the site, enter the password once, and download.

Nothing is stored on the server; files are built in the browser.

## Local test (no real Xola needed)

```
node test/run-test.js        # API tests against a fake Xola (raw reports)
node dev-server.js 3000      # needs APP_PASSWORD, XOLA_API_KEY (and XOLA_BASE for a fake server)
```
